Technical report · on-chain-llm

A transformer that runs inside the Ethereum Virtual Machine

Stock EVM, no precompiles, no custom node, nothing computed off chain. Two models are live on Base Sepolia and generate text from contract storage.

Richard Chung github.com/richardjaee/on-chain-llm companion report: tensor-evm

1 Why this was thought impossible

When a language model answers a question, there is no way to check that the model you paid for is the model that ran. The weights sit on someone else's hardware, the arithmetic happened in a process you cannot inspect, and the log recording it is written by the party you would be auditing.

The usual remedies add a trusted component. Zero-knowledge proofs move the computation off chain and verify a proof instead, at a cost between one hundred and ten thousand times plain inference. Trusted execution environments cost about five percent but require trusting a hardware vendor whose enclaves have been broken repeatedly. Optimistic schemes assume an honest challenger appears inside a dispute window.

A fourth option needs none of them. If every node recomputes the inference independently and they all agree, the answer is verified by consensus, the same mechanism that verifies a token transfer. Nobody has to be trusted. The reason that option is usually dismissed is specific:

Floating-point addition is not associative, so the order a sum accumulates in changes its last bits. GPU reduction order varies with the kernel selected, the thread count, and the batch a request lands in. Two honest machines running the same weights on the same prompt return different logits.

If honest nodes can disagree, a disagreement carries no information and consensus has nothing to work with. Integer addition is associative, integer multiplication is exact within its width, and no rounding mode is left to the implementation. Make the entire forward pass integer and reduction order stops mattering, which makes reproduction free rather than expensive.

Everything below is built on that one observation.

2 What is deployed

Every multiply-accumulate in these contracts executes as EVM opcodes. Weights are quantised to 16-bit integers with a power-of-two scale per row, activations are Q32 fixed point, and accumulation happens in 128 bits. The prompt goes in as token ids and the answer comes out of storage. The chain is one the author does not control.

3 How a forward pass fits in a block

Resumable inference

A single forward pass costs far more gas than any RPC provider accepts in one transaction, roughly fifteen million in practice. That limit is separate from the block gas limit, so the model could never be run by simply calling it, however large blocks became.

The contract removes that ceiling by making inference resumable. Each step runs one or more layers for the current position, then checkpoints the residual stream and that layer's key-value cache row into storage. The next transaction reloads and continues. Total compute is unbounded while each transaction stays small, which is why one sentence takes a thousand transactions rather than one.

Weights as code, not storage

Holding 30.5 MB in contract storage would cost twenty thousand gas per thirty-two bytes. Deploying the same bytes as contract code and reading them with EXTCODECOPY costs roughly a third of that. The weights live across 1,241 data contracts, and the addresses of those contracts are themselves stored as data contracts, because one directory holds at most 1,228 of them.

4 Mixture of experts

Gas follows the parameters a token reads, and a dense layer reads all of them. A router that visits two experts of eight skips most of the layer, and every skipped chunk is a data contract never touched. Sparsity is the one change that moves the ceiling by an order of magnitude rather than a few percent.

Two things have to be reproducible here. The arithmetic, as everywhere. And which experts are chosen, which is the sharper requirement: a tie broken differently is not a rounding difference, it routes the token through different parameters, so two honest nodes emit different text and the chain forks. Ties go to the lower index, everywhere, and that rule is tested rather than assumed.

5 Limits

Cost is real. On Base mainnet at current prices, the 8.83 billion gas that produced six tokens of TinyStories would cost roughly 159 dollars, about 26 dollars a token, against something near a hundredth of a cent for a hosted model. Public rollups price generic computation for transfers and swaps. Serving a model this way needs an execution environment whose gas schedule you set yourself.

Every input is public. Re-execution requires each validator to see the prompt, so this architecture cannot serve confidential data, and the weights must be published for the same reason. A closed model cannot run here.

Context is bounded. Attention grows with position. Running more layers per transaction moved the reachable position from 48 to 286, and test_FindStrandPosition pins where a run strands.

Scale is the open problem. At one billion parameters a token needs on the order of ten thousand transactions, roughly a hundred blocks of sequencer capacity with nothing else in them, after depositing gigabytes of weights across tens of thousands of contracts.

The last two points are what the companion project exists to attack. If the interpreter is the constraint rather than gas, the next question is what happens when the virtual machine itself is changed. That report is here.
